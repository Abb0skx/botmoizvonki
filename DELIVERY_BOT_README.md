# TEXNIKACH Delivery Bot

Рабочий MVP Telegram-бота для создания и сопровождения доставок. Instagram-модуль проекта не изменяется.

## Возможности

- менеджер создаёт заказ и изменяет его до отправки, а также в статусах ожидания и выезда;
- перед созданием выбирается владелец заказа: `Olmas`, `Otabek`, `Ali` или `Abbos`;
- один или два телефона, цена и одна или две локации принимаются в любом порядке;
- две ссылки на карты можно прислать одним сообщением, а две Telegram Location — подряд;
- менеджер выбирает оплату при доставке или вариант `Оплачено при сборе товара`;
- кнопка `✅ Доставлено` сразу завершает заказ без запроса фото и суммы;
- кнопка `📋 Активные заказы` показывает всем менеджерам черновики и незавершённые заказы со статусами;
- над списком активных заказов есть кнопка общей Яндекс-карты со всеми основными и дополнительными локациями;
- кнопка `📚 Все заказы` показывает всем менеджерам также доставленные и отменённые заказы;
- длинные списки показаны компактно по 10 заказов в одном информационном сообщении; кнопки страниц обновляют это же сообщение и не создают дубли рабочих карточек;
- курьер может начать и отменить выезд без отмены самого заказа;
- район, махалля и адрес определяются по координатам через OpenStreetMap и
  показываются одной короткой строкой;
- у заказа может быть одна или две локации; дополнительную точку можно добавить
  сразу при создании или позднее через изменение заказа;
- бот публикует обычную Telegram Location в отдельном приватном канале и следом
  текстовый блок со статусом, товаром, суммой, телефонами, временем, комментарием
  и коротким адресом;
- возле публикации локации остаётся одна кнопка `💬 Telegram клиента`;
- в карточке заказа остаются ссылки `📍 Локация` и `📍 Доп. локация`;
- при изменении координат старая точка помечается как устаревшая, а карточка
  автоматически получает ссылку на новую Telegram Location;
- команда `/map` и кнопка карты над активными заказами показывают нумерованную
  легенду моделей и до 25 основных/дополнительных точек на одной карте;
- незавершённое создание и изменение заказа сохраняются между перезапусками;
- кнопка `🔄 Синхронизировать` восстанавливает карточку группы или публикацию
  локации после временной ошибки Telegram.

## Запуск

1. Создайте бота через `@BotFather`.
2. Добавьте бота в группу доставки администратором с правом отправлять и изменять сообщения.
3. Создайте приватный канал локаций, добавьте туда сотрудников, а бота назначьте
   администратором с правами публикации, изменения и удаления сообщений.
4. Скопируйте `.env.example` в `.env` и заполните токен, ID группы, канала локаций,
   менеджеров и курьеров.
5. Установите зависимости: `pip install -r requirements-delivery.txt`.
6. Запустите из корня проекта: `python -m app.main`.

Для отдельного Docker-сервиса используйте `Dockerfile.delivery`. Каталог `/app/data`
нужно подключить как постоянный volume, иначе SQLite-база будет потеряна при пересоздании контейнера.

На VPS можно использовать `compose.delivery.yaml`: создайте рядом файл `.env.delivery`
с production-переменными и выполните `docker compose -f compose.delivery.yaml up -d --build`.
Именованный volume `texnikach-delivery-data` сохраняет базу между пересборками.

ID группы и канала можно узнать через временный вызов Telegram API `getUpdates`
после сообщения. ID пользователей — через `@userinfobot`. Ссылки вида `t.me/c/...`
открываются только у участников приватного канала, поэтому каждый курьер должен быть
добавлен в канал локаций.

База создаётся и обновляется автоматически. Номер заказа выдаётся транзакционно и
не повторяется. Изменения и переходы статусов записываются в журнал событий SQLite.
Состояние незаконченного диалога хранится в `delivery-state.pickle` рядом с базой.

Команда `/cancel` прекращает текущий ввод. Списки менеджеров и курьеров обязательны: бот не запустится с открытым доступом.
