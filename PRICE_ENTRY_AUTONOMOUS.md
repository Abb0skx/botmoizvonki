# Самостоятельный ввод цен

`/price/entry` по умолчанию использует локальное SQLite-хранилище. Google Price
не является рабочим источником и не используется как автоматический fallback.
Неподготовленная локальная база возвращает 503, а не обращается к Google.

## Данные и запись

- `entry_products`: один общий каталог, неизменяемые существующие ID.
- `entry_suppliers`: существующие поставщики и стабильные идентификаторы.
- `entry_prices`: только заполненные предложения поставщиков.
- `entry_input_state`: версия данных и отпечаток первоначального переноса.
- `price_entry_operations`: прежний журнал операций сайта.
- `entry_categories`: канонические ID и названия категорий.
- `entry_catalog_state`: следующие свободные ID категорий, товаров и версий.
- `entry_catalog_operations`: идемпотентный журнал добавления моделей.

Цена, версия данных и журнал записываются одной SQLite-транзакцией. Проверка
ревизии предотвращает потерю параллельных правок; UUID запроса обеспечивает
идемпотентный повтор после разрыва соединения. Минимальная цена рассчитывается
по всем поставщикам. SQLite backup API сохраняет все новые таблицы автоматически.

## Worker

`price_server/worker_input.py` — самостоятельный модуль для установки как
`Cod/server_price_source.py` в **серверный** worker. Точное изменение импортёра
сохранено в `scripts/price_worker_server_input.patch`; перед применением проверить
`patch --dry-run -p1`, при уже применённом — `patch --dry-run -R -p1`.
При `PRICE_INPUT_SOURCE=server`
импорт получает `GET /price/api/v1/entry/export` с существующим `X-Price-Sync-Key`.
Адрес строится из `PRICE_SERVER_URL`, так же как текущая отправка snapshot.
Проверяются схема, контрольная сумма, ID, категории, поставщики и диапазон цен.
Редиректы и возврат к старым Google-ценам запрещены. Последующие расчёты,
staging/backup worker, HTML и публикации остаются прежними.

Это замена **Google Price**, не удаление всех Google-интеграций: Product Sort,
курс и список исключённых товаров остаются прежними. Каталогом моделей теперь
управляет сайт. Старый импорт Products/Categories при серверном режиме должен
быть отключён, чтобы два источника не могли выдать одинаковые ID.

Кнопка «Добавить модель» создаёт один или несколько вариантов товара. Сервер
атомарно назначает `product_id`, версии гарантии 1/12 месяцев и при необходимости
новый `category_id`. Общий `entry_products` делает новые варианты сразу видимыми
у всех поставщиков с пустыми ценами. Очередной импорт worker сначала добавляет
категории, товары и версии в свою staging-БД, затем проверяет и заменяет цены.
Существующие worker-товары, отсутствующие в активном каталоге сайта, не удаляются.
Любой конфликт ID откатывает весь импорт.

## Безопасный перенос

1. Прогнать тесты. Зафиксировать runtime-образы и архив исходного кода.
2. Создать защищённую проверенную SQLite-копию через `create_backup`.
3. Установить код без переключения источника. На время переноса включить
   `PRICE_ENTRY_WRITES_PAUSED=true`, дождаться завершения текущего импорта.
   Не редактировать исходную Google Price в это окно.
4. `python -m price_server.entry_migrate capture /app/data/backups/<release>/input.json.gz`.
   Двойное чтение проверяет стабильность всех листов, архив проверяется распаковкой.
5. SQLite backup API создать отдельную тестовую БД. Выполнить на ней:
   `python -m price_server.entry_migrate install <archive> --database <test-db>`;
   затем `check` с теми же аргументами. Сверяются все ID, описания, цены, ревизии.
6. Только после успешной проверки выполнить `install` и `check` рабочей БД.
7. Перед включением кнопки каталога передать в `entry_catalog_migrate` полный
   список категорий и максимальные ID из worker. Сначала проверить точную копию
   production-БД, затем повторить на рабочей базе.
8. Переключить web на `PRICE_ENTRY_SOURCE=sqlite`, снять паузу записи.
   Переключить только scheduler/dispatcher/runner worker на `PRICE_INPUT_SOURCE=server`
   и обновлённые образы; остальные контейнеры не перезапускать.
9. Проверить auth, API, SQLite, worker export и очередной штатный импорт.

Миграция добавочная, существующие таблицы прайса/постов/заданий не изменяет.
Повтор с тем же архивом ничего не перезаписывает, с другим — отклоняется.

## Откат

При неисправности кода после начала работы **не переключать источник на Google**:
там уже устаревшие цены. Сначала остановить запись и сохранить новую SQLite-копию.
Исправить код или вернуть предыдущие образы вместе с защищённой SQLite-копией,
созданной непосредственно перед миграцией каталога. Google-таблица после перехода
не является допустимым источником отката: там нет свежих цен и созданных на сайте
моделей. Новые таблицы не удалять отдельно. Восстановление всей БД — только при
повреждении, с остановкой писателей и проверкой архива, иначе можно потерять
свежие задания и Telegram message_id.

Ни миграция, ни сохранение цен сами по себе не отправляют Telegram-посты.
Цены подхватываются очередным штатным импортом (сейчас каждые 30 минут).

## История отдельной ячейки

Кнопка «История» под каждой ценой открывает журнал именно этой ячейки:
поставщик + product_id/version_id_1/version_id_12 + price_1 или price_12.
Показаны время в серверном часовом поясе, прежнее и новое значение. Очистка
цены также сохраняется. Несохранённые черновики не входят в историю.

Защищённый GET `entry/cell-history/{sheet_id}/{product_key}/{field}/{before}`
возвращает до 50 записей и `next_before`; для первой страницы `before=0`.
Новые операции во время просмотра не сдвигают старые страницы. В отличие от
общего журнала последних 100 операций, здесь доступен весь сохранённый журнал
ячейки. Индекс по поставщику ускоряет поиск, сами изменения не дублируются:
используется существующий `price_entry_operations.changes_json`.

Сохраняется история правок сайта, включая прежние операции в режиме Google.
Прямые изменения Google Price, сделанные вне сайта, не импортировались.
Старые неподтверждённые Google-записи явно помечаются как неподтверждённые,
а не выдаются за успешно применённые цены.
